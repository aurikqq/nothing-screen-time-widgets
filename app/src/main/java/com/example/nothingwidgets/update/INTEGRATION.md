# Обновления из GitHub Releases

Доверенный источник: `aurikqq/nothing-screen-time-widgets`, точное имя APK: `nothing-widgets.apk`. Используется `/releases/latest`: черновики и prerelease отвергаются. До загрузки баннер появляется только при численно более новом стабильном теге вида `v0.7`, `0.7.1` относительно `versionName`; стабильный `0.6` считается новее `0.6-dev`. Неизвестные форматы тегов не предлагаются. Реальная возможность обновления определяется после скачивания по `versionCode`, пакету и сертификатам.

## Подключение Activity

```kotlin
// onResume, после создания элементов баннера:
UpdateController.attach(this) { state ->
    // state.visible — показывать баннер; state.tag/notes — версия и описание релиза.
    // state.downloading — заблокировать действие; progress 0..100, -1 — ожидание/проверка.
    // state.readyToInstall — действие «Установить», иначе «Скачать».
}
// onPause:
UpdateController.detach(this)
// Явные нажатия:
UpdateController.download(this)
UpdateController.install(this)
// Повторная metadata-проверка:
UpdateController.checkManual(this)
```

`UiState` неизменяемый: `visible`, `checking`, `downloading`, `readyToInstall`, `tag`, `notes`, `message`, `progress`. Последнее состояние доступно через `getState()`. Callback приходит в основном потоке. `attach` сразу отдаёт состояние и запускает проверку; параллельные сетевые операции объединяются. Если уже скачана проверенная APK, она восстанавливается и одновременно проверяется metadata. Более новый стабильный релиз заменяет старый кандидат: сохранённая старая APK удаляется только из проверенного приватного каталога. При возврате после отменённой загрузки или системной установки кнопка позволяет повторить действие.

Загрузка начинается только по нажатию. После проверки баннер предлагает «Установить». Если Android ещё не разрешил установку из этого приложения, нажатие открывает настройки источника; после возвращения с разрешением ранее запрошенная установка продолжается автоматически. Окончательное подтверждение остаётся в системном установщике. Дополнительный диалог приложения не нужен.

## Сохранность и безопасность

Скачанная APK и metadata сохраняются в приватном хранилище. После перезапуска проверяются заново SHA-256, размер, packageName, versionCode и сертификаты. Повреждённая, устаревшая или подписанная другим ключом APK не устанавливается. Повторная проверка перед установкой и хеширование байтов сессии PackageInstaller сохранены. Состояние запроса разрешения также сохраняется, поэтому установка продолжается после возврата даже при пересоздании процесса.

APK после отмены системного установщика сохраняется для повторной попытки; успешный callback удаляет файл и запись. Непригодная сохранённая APK удаляется, только если её канонический путь находится непосредственно в приватном каталоге updates. Незавершённая загрузка после уничтожения процесса не возобновляется по байтам: её потребуется запустить заново. Системный confirmation Intent хранится в процессе и, если разрешены уведомления, в PendingIntent уведомления; его восстановление после уничтожения процесса без уведомлений не гарантировано. В таком случае доступна повторная установка сохранённой APK.

HTTPS, допустимые хосты GitHub, ограничение редиректов, JSON до 1 MiB, APK до 150 MiB, таймауты, обязательный GitHub SHA-256 digest сохранены. Ключи подписи должны точно совпадать; ротация ключей и обновление debug-сборки release-ключом не поддерживаются. Не поддерживаются split APK и GitHub Enterprise. Коммит сессии не означает успех: только `STATUS_SUCCESS` подтверждает установку.

Manifest должен содержать INTERNET, REQUEST_INSTALL_PACKAGES, POST_NOTIFICATIONS и неэкспортированные UpdateInstallReceiver / UpdateConfirmationActivity. WorkManager уже используется для дополнительной суточной metadata-проверки, не запускающей загрузку. Основная проверка работает при каждом входе в Activity независимо от уведомлений. Ручная `checkManual` показывает ошибки и сообщение «Релизы ещё не опубликованы» (GitHub 404) с возможностью повторить проверку; автоматическая проверка без доступного обновления баннер не показывает.

## Проверка

`ReleaseVersionTest` покрывает новые/старые/равные версии, числовой порядок, dev → stable, неизвестные/prerelease теги, null и защиту от переполнения. Сборка и запуск Android-тестов проверяются в рамках общей сборки проекта. Реальная публикация релиза, скачивание подписанного release APK и системная установка требуют отдельной проверки на устройстве; релиз этим изменением не публикуется.

Источники: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release), [GitHub asset digest](https://docs.github.com/en/rest/releases/assets), [Android PackageInstaller](https://developer.android.com/reference/android/content/pm/PackageInstaller).
